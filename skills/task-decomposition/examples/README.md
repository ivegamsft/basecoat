# Task Decomposition Examples: Good vs Bad

This folder contains side-by-side comparisons of good and bad task decompositions.

## Files

- `example-1-api-feature.md` — Adding a new API feature
- `example-2-refactoring.md` — Refactoring an existing module
- `example-3-system-redesign.md` — Large system redesign (likely too big for automation)

Each example shows:
1. **Bad Decomposition** — What NOT to do (vague, unclear, or unrealistic)
2. **Good Decomposition** — Clear, parallel, ready for sub-agents
3. **Key Lessons** — Why the good version works better

---

## How to Use These

1. When you're unsure about how to decompose a task, find a similar example.
2. Compare your decomposition against the "Good" version.
3. Use the "Key Lessons" as a checklist for your own work.
4. If you find a pattern not covered here, consider adding a new example.
